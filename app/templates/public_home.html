Project ownership

Designed and developed by Artem Herasymenko

I structured and validated the basketball data, designed the database workflow, and built the season, roster, and game management tools. I implemented reusable statistical calculations and analytics views, developed the FastAPI application, tested it, and deployed it on Railway.

CourtStats connects two parts of that work: a public analysis that readers can examine, and an authenticated application for maintaining operational records.

Why I built it

A workflow that outgrew the spreadsheet

The project began with manually recorded game statistics. Structuring them in spreadsheets made season analysis possible, but repeated calculations and workflow limitations exposed the need for persistent records, input validation, and reusable analysis. CourtStats carries that work into an application.

Engineering approach

Raw records first. Derived metrics second.

  1. Browser
  2. FastAPI routes
  3. Service layer
  4. SQLAlchemy
  5. PostgreSQL

Raw game statistics remain the foundation. The service layer derives metrics consistently; shooting percentages use combined makes divided by combined attempts rather than averages of individual percentages.

External games stay separate from official season totals. Automated tests cover calculations, validation, authentication, and operational workflows. The public case study uses a static snapshot rather than live database records.
